- `main_panel.py` — the root panel Karcytics injects (`PluginBase` subclass). Intentionally thin: layout wiring + the required interface (`signals`, `export_state`/`load_state`, `export_workflow`/`load_workflow`) plus instantiating `GateController`/`GatePropagator`. Complex widgets belong in `widgets/`, `graph/`, or `ribbons/`, not here.
- `composition_root.py` — `ServiceFactory.build_all()` is the one place that constructs and wires every domain/infrastructure service (axis manager, population service, gate coordinator, data loader, UMAP service, workspace I/O). Add a new service here, in dependency order, rather than constructing it ad hoc where it's used. The `logger.warning("[phase1] ...")` breadcrumbs are temporary diagnostic instrumentation for tracing exactly which service construction step a stalled isolated-process daemon hangs on — if you're debugging a startup hang, read these; if you're adding a new service, add a breadcrumb around it too rather than removing the existing ones.
- `scope_resolution.py` — the single shared helper for "which samples does a scoped action affect" (`"sample"` vs `"group"`, including the `group_id == "all"` case). Any UI action that operates on a scope should call `resolve_target_samples` rather than re-implementing this branching.
- Imports here go through `karcytics_sdk.plugin.runtime_services` (`task_scheduler`, `event_bus`, `tutorial_manager`) and `karcytics_sdk.plugin.theme_fallback` (`Colors`, `Fonts`, `theme_manager`) — never `karcytics.core.*` or `karcytics.ui.theme` directly, since this plugin runs `isolated` (see this repo's root `CLAUDE.md`).
